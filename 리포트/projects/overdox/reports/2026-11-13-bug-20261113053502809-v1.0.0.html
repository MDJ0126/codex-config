OOVERDOX 복원버그

히드라 탈진 미적용과 앞선 구현 설명 정정

검토

전설 검의 피해·순간이동은 연결됐지만 탈진501의 타입60을 처리하지 않아 탈진은 적용되지 않습니다. 앞선 적용 완료 설명을 정정합니다.

접수→검토→진행→해결→종료
2026년 11월 13일 오후 2:35 KSTv1.0.0버그 추적

작업 결과

앞선 고유 스킬 보고서의 “탈진을 적용했습니다” 설명은 잘못됐습니다. 피해와 순간이동 경로가 있다고 참조된 상태효과까지 실행된 것으로 판단했습니다. 현재 탈진은 미구현입니다.

정정 대상: 전설 검 투척·순간이동 보고서. 기존 글은 기록으로 보존하며 이 후속 글에서 오류와 실제 지원 범위를 바로잡습니다.

변경 내용

재현 조건

Unity6000.0.83f1, 검토용 build16. 사용자 PC 사용·검토 요청 후 새 게임 실행이나 GUI 입력 없이 기존 소스·원작 표를 정적으로 대조했습니다.

재현 순서

원작 Gear10150→Skill10014→HitReference1024→ConditionEffect501을 대조합니다. ThrowAndTeleport의 ApplyCondition 호출과 ApplyCondition의 ConditionType 분기를 확인합니다.

기대 동작

히드라의 순간이동 후 범위 타격에 맞은 대상에게 원작 설명의 탈진 상태가 적용되어야 합니다.

실제 동작

ConditionEffect501의 ConditionType은60입니다. ApplyCondition은1·2·3·4·25만 지원하고 나머지를 null로 만들어 즉시 반환합니다. 탈진 스택·효과는 추가되지 않습니다. 이는 정적 경로 확인이며 새로운 실제 플레이 재현을 했다는 뜻은 아닙니다.

원인

상태 참조 ID 연결과 지원 처리 분기를 함께 확인하지 않았고, 장비별 스킬 검증에서도 ConditionType60의 발동을 독립 검사하지 않았습니다.

적용 내용

문서의 지원 범위를 정정하고 README·Parity·장비별 검토 목록에 알려진 누락을 추가했습니다. 실행 코드 변경 없음. 아래는 현재 ApplyCondition 전체입니다.

flowchart TD
    A[히드라 범위 타격] --> B[ConditionEffect501 조회]
    B --> C[ApplyCondition 호출]
    C --> D[ConditionType60]
    D --> E[지원 목록에 없어 status=null]
    E --> F[즉시 반환·탈진 미적용]

public void ApplyCondition(Overdox.OriginalData.ConditionEffect condition,int count=1)
{
    string status = condition.ConditionType switch { 1 => "Burn", 2 => "Frost", 3 => "Bleed", 4 => "Shock", 25 => "Root", _ => null };
    if (status == null || status == "Burn" && Effects.Sum(36) > 0 || status == "Bleed" && Effects.Sum(37) > 0) { return; }
    if(_conditions.Add(condition,count,Time.time,_conditionRecovery))
    {
        Impact?.Invoke(this,condition.ConditionType switch {1=>"화상",2=>"동상",3=>"출혈",4=>"감전",_=>"속박"},0);
        ArenaSession.Instance.Record("condition-"+condition.ConditionType);
    }
}

검증

소스·데이터 정적 대조 기록. Source SHA256와 원작 ID 경로를 기록했습니다. 실제 실행에서 해당 효과만 분리한 재검증은 아직 하지 않았습니다. 기존35개 검사와38종 명중 검사는 이 누락을 검사하지 않으므로 통과 근거로 사용하지 않습니다.

남은 사항

사용자 검토 요청에 따라 실행 빌드와 전투 코드는 변경하지 않았습니다. 원작 효과 공식 확인, 구현과 독립 런타임 검증이 남아 있습니다. 이 글은 문제 해결 보고가 아닙니다.

작업 시간

  • 제안 시간: 추가 기능 구현은 중단하고 전달 기록을 정리하는 범위입니다. 별도 구현 소요는 아직 산정하지 않았습니다.
  • 실제로 완료된 시간: 2026-11-13 14:34 KST 무렵 정적 대조에서 확인했습니다. 검토본 전달14:03 KST 이후 문서만 정정했으며, 실행 수정 완료 시각은 없습니다.
  • XERJ: 미사용 — XERJ 연결·검색 없음. rg와 기존 소스·원작 표를 대조했습니다.
