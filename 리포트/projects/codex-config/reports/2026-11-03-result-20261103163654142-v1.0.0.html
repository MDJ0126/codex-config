Affinity 저장 권한 오류는 프로젝트 폴더 복구 후 검증

완료

권한 오류 보고로 중단하지 않고, 해당 프로젝트 권한을 직접 복구한 뒤 실제 저장·재열기까지 검증하도록 지시했습니다.

2026년 11월 4일 오전 1:36 KSTv1.0.0설정

작업 결과

전역 지침과 공개 작업 가이드에 저장 권한 복구 절차를 반영했습니다.

변경 내용

적용 내용

  • 실제 오류·프로젝트 경로·실행 계정·소유자·ACL·Affinity 접근 허용 범위를 먼저 확인합니다.
  • 원인에 맞춰 해당 프로젝트 폴더의 쓰기·수정 권한과 상속 또는 앱 접근 허용을 복구합니다. 기존 ACL은 보존합니다.
  • 임시 파일 생성·수정·삭제와 실제 Affinity 원본 저장·재열기·출력 파일을 확인할 때까지 진행합니다.

검증

전역 설치본·주 저장소·격리 저장소 지침의 SHA256 일치, 945개 보고서 빌드·33,344개 링크 검사를 통과했습니다. 공개 작성·작업 가이드와 GitHub main 지침3곳의 실제 문구를 확인했습니다. 공개 확인 기록

남은 사항

이번 요청은 지침 변경입니다. 실제 실패 파일이나 프로젝트 폴더의 ACL을 바꾸거나 Affinity 저장 성공을 검증한 것은 아닙니다. 문서 작업이므로 실행 화면을 만들지 않았습니다.

교훈 검토: 추가 — 사용자 지시에 따라 저장 오류를 프로젝트 범위에서 직접 복구하고 실제 저장까지 검증하는 규칙을 추가했습니다. 다른 프로젝트·드라이브 전체로 권한을 확대하지 않으며 실제 관리자 제한은 구분합니다.
