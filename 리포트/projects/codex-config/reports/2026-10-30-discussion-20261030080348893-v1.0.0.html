논의 중

기존 Affinity CLI 글2건에서 음수 소요 시간을 확인했습니다. 원문은 보존하면서 시간 계산의 정정 근거와 새 글 등록 검사를 어떻게 둘지 논의합니다.

2026년 10월 30일 오후 5:03 KSTv1.0.0부족한 점

토론 내용

과거 원문2건에 음수 소요 시간이 기록돼 있어 정상적인 경과 시간으로 읽을 수 없습니다. 본문에 시작·종료 시각도 있으므로 두 시각의 차이와 작업 범위를 확인해 정정 이력을 남길 필요가 있습니다. 전체 작업 완료와 일부 단계 완료가 섞였는지 여부는 미확인입니다.

QA 근거와 맥락

검토한 원문:

Affinity 전용 CLI 구현·보관 및 전역 지침 연동

실제로 완료된 시간: 구현·자동 검증·전역 적용·원격 보관과 보고서 원본 작성까지 -524 분 -19 초.

Affinity 전용 CLI 개발 범위와 예상 시간

실제 소요 시간: 상태 확인·견적·보고서 원본 작성까지 -32368 초

문서 원문의 값과 두 시각을 확인한 것이며 제품 실행 시간을 새로 측정하지 않았습니다.

제안 및 대안

  1. 원문·버전은 그대로 보존하고 정정 근거와 새 버전을 연결합니다.
  2. 시작·종료 시각의 시간대와 완료 범위를 대조한 후 실제 경과 시간을 계산합니다.
  3. 신규 보고서에 음수 경과나 종료가 시작보다 앞선 시각이 있으면 등록 전 확인하도록 제안합니다. 자유 서술을 임의 숫자로 대체하지 않습니다.

결정과 후속 작업

아직 결정되지 않았습니다.

부분 단계와 전체 완료의 경계가 확정되기 전에는 계산한 값을 실제 작업 총시간으로 단정하지 않습니다. 이번 작업에서는 과거 원문을 덮어쓰거나 시간 검사를 구현하지 않았습니다.

작업 시간

  • 제안 시간: 전체 기존 글 검토·논의 등록 20~35분 공통 작업
