## 작업 결과

미리보기 배율·버튼·정렬·기존 세션 처리를 수정하고, 실제 Unity UI Toolkit 패널에서 레이아웃 12조건과 배율·세션 8항목을 검증해 통합 브랜치에 푸시했습니다.

## 변경 내용

### 재현 조건

Windows · Unity 6000.0.83f1 · Pixora Studio. 수정 검증은 화면을 띄우지 않는 실제 Unity UI Toolkit 에디터 패널 배치 실행입니다.

### 재현 순서

256×256 원본과 64×64 결과의 100% 보기를 확인합니다. 별도 실제 패널에서는 바깥 미리보기 크기를 고정하고 내부 뷰포트를 440×360에서 380×240으로 바꿔 canvas·image 좌표를 비교했습니다.

### 기대 동작

기본 보기는 각 뷰포트에 맞게 중앙에 표시하고, 크기가 바뀌면 배치를 갱신해야 합니다. 100%에서는 실제 픽셀 크기를 유지해야 합니다.

### 실제 동작

100%에서는 서로 다른 텍스처 해상도만큼 크기가 달랐습니다. 수정 전 재현 패널은 내부 높이가 240으로 바뀌어도 캔버스 높이가 360에 남아 중심 오차가 60이었고, 화면 맞춤 이미지도 이전 360 크기에 남았습니다.

### 원인

기존 코드는 ScrollView 바깥 GeometryChangedEvent만 관찰하면서 크기 계산에는 내부 contentViewport를 사용했습니다. 내부 뷰포트만 바뀌면 갱신이 누락되는 것을 실제 레이아웃 좌표로 재현했습니다.

### 적용 내용

contentViewport 크기 변경을 직접 관찰하고 이미지를 캔버스 중앙 좌표에 배치합니다. 기본 화면 맞춤과 실제 100% 버튼을 분리했습니다. 기존 기본 100%만 한 번 화면 맞춤으로 전환하고 기존 다른 배율과 이후 선택한 배율은 창별로 보존합니다. 9개 언어 문서·생성 HTML·실제 크기 버튼 번역을 갱신했습니다. 변환 출력 해상도나 PNG 데이터는 변경하지 않았습니다.

## 검증

64·256px 텍스처, 100%·화면 맞춤·400%, 내부 크기 변경의 실제 Unity 레이아웃 12조건이 통과했습니다. 수정 후 64px 100%는 64 화면 픽셀을 유지하고 중심 오차는 0, 화면 맞춤은 새 높이 240 안에 들어갑니다. 신규/기존 세션·기존 사용자 배율·창별 독립성 등 8항목이 통과했습니다. 9개 언어 54장·54개 코드 예제와 프로젝트 문서 10장의 5개 이미지 링크 검사도 통과했습니다. 최종 줄바꿈·공백 검사를 통과했습니다. ## 남은 사항

화면 조작 보류 요청을 유지해 실제 데스크톱 창에서 외관·상호작용 재확인이나 새 캡처를 하지 않았습니다. 사용자 화면의 정확한 이벤트 순서는 미확인입니다. 내부 뷰포트 크기 변경 누락을 별도 실제 패널에서 재현·수정했습니다. 자동 승인 검토가 사용자 캡처의 공개 게시 승인을 확인할 수 없다고 거절했으므로 중앙 보고서는 이미지를 제외하고 좌표 자료만 공개합니다.
