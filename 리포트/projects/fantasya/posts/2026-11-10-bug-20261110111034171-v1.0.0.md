## 작업 결과

FantasyaCharacter를 GUID로 로드할 때 사용자가 제공한 InvalidKeyException 로그를 확인했습니다. 그룹 직렬화를 수정했습니다.

## 변경 내용

### 재현 조건

Fantasya의 Unity 6000.0.83f1 및 Addressables 2.9.1

### 재현 순서

Playground에서 캐릭터가 초기화되면 DDT가 FantasyaCharacter 바이너리를 GUID로 요청합니다. 사용자 로그에 남은 실행 경로입니다.

### 기대 동작

GUID로 등록한 테이블 바이너리를 읽어 캐릭터를 초기화합니다.

### 실제 동작

사용자 콘솔에 InvalidKeyException과 DDT 로드 실패가 기록됐습니다.

### 원인

번역 항목을 잘못 삽입해 Design Data Tables 그룹 목록의 YAML이 손상됐습니다.

### 적용 내용

- 이전 보고에서는 등록 주소와 파일 참조를 대조했다고 밝혔습니다. 그 확인은 주소 문자열의 존재를 확인했으며, 그룹 목록의 구조가 깨진 사실은 놓쳤습니다.
- `Design Data Tables.asset`에는 번역 항목이 반복 삽입되면서 테이블 항목의 YAML 구조가 깨져 있었습니다. 테이블 바이너리 26개와 번역 참조 에셋 1개를 한 목록으로 복구했습니다.

```yaml
- m_GUID: 12d5ece039f4bda4c9b4f15ac07ac70e
  m_Address: DesignDataTable/FantasyaCharacter
  m_ReadOnly: 0
  m_SerializedLabels: []
```

### 대화 기록

1. 사용자 · 미기록 · “No Location found for Key=12d5ece039f4bda4c9b4f15ac07ac70e.” 오류를 제공했습니다.
2. Codex · 11월 9일 21:10 KST · 잘못 삽입한 번역 항목을 정리하고 GUID 일치를 확인했다고 보고했습니다. 기존 콘텐츠를 사용하는 경우에는 재빌드가 필요하다고 설명했습니다.

## 검증

사용자 로그의 GUID를 DDT 레지스트리 및 복구된 그룹 항목과 대조했습니다.

## 남은 사항

수정 후 Unity에서 해당 로드 경로를 다시 실행한 기록과 전후 화면은 미확보 상태입니다.

## 작업 시간

- 제안 시간: 원 작업별로 채팅에 안내했습니다. 누락분 정리 초안은 5~10분으로 제안했습니다.
- 실제로 완료된 시간: 원 작업별 소요 시간은 개별 작업 응답에 기록했으며 합산하지 않았습니다.
- XERJ: 미사용 — 코드 검색 근거가 제공되지 않았습니다.
