먼저 AGENTS.md, 아래 인계/QA 보고서, manualId=turnroom-excel-ribbon-parity-20261031의 최신 버전, 프로젝트의 기존 QA 기록을 읽으세요. 현재 기준 메뉴얼은 v1.0.10이며 기존27개 작업을 보존하고 전체 단축키 작업 T28을 추가한28개입니다. 원래 완료 기준을 줄이거나 미구현을 다른 기능·빈 핸들러·목록 작성으로 대체해 완료 처리하지 마세요.

첫 미완료 작업부터 구현→실제 Unity 실행→정상/오입력/반복/취소/Undo/Redo/저장/재열기 QA→실패 원인 확인/수정→재QA→영향 회귀를 계속하세요. 피벗·슬라이서·타임라인·스파크라인·그리기·SmartArt·그래픽·3D·VBA/Office Scripts/추가 기능 등 원래 남은 범위를 유지하세요. 피벗을 일반 집계표나 이미지로 대신하고 실제 피벗 지원이라 부르지 마세요. 원본 Excel 이미지와 현재 화면을 케이스별로 대조하고 최신 실제 화면·원본 출처·버전 차이를 남기세요.

단축키는 Microsoft 공식 문서의 Windows Excel 목록 전체(동시 조합·기능키·Alt KeyTips 순차 입력 포함)를 원문/출처/확인 시각/버전/키보드 배열과 함께 수집하세요. Windows/Mac/Web 목록을 섞지 마세요. 각 항목을 기능·포커스 문맥·현재 바인딩·실행 코드·TC·결과/증거에 매칭하고 빠진 동작을 구현하세요. 기존134개 비입력 바인딩·2100정적 검사는 공식 전체 목록이나 실제 입력 통과를 뜻하지 않습니다.

그리드·셀 편집·수식 입력·팝업·개체·리본 문맥을 구분하세요. F4는 수식 참조 고정 순환과 편집 밖 반복처럼 문맥별 Excel 동작을 맞추세요. Ctrl+S/D/K/F/G 등 겹치는 키는 실제 Excel 창이 키보드 포커스를 소유할 때만 Excel에서 소비하고, 그 밖의 Unity Scene/Project/Inspector/Game에서는 기본/사용자 Unity 단축키를 그대로 동작시키세요. Unity 전역 단축키 프로필을 수정/해제하거나 전역 핫키를 등록해 충돌을 숨기지 마세요. OS 예약키·IME·한/영·팝업·포커스 왕복·반복/장시간 입력을 포함하고 Excel→Unity와 Unity→Excel 양방향으로 실제 키 입력을 검증하세요. Ctrl+K가 링크 창과 Unity 검색을 동시에 여는 회귀도 반복 검사하세요.

검사 목록·바인딩 존재·정적 단언과 실제 Windows API 키 입력 결과를 분리하세요. 재사용 QA 프로젝트의 실제 코드/로드된 컴파일/폰트/에셋이 제품과 일치하는지 확인하고, PID·프로세스 경로·프로젝트·UTC 생성 시각으로 소유권을 확인한 뒤 조작하세요. 사용자가 컴퓨터 사용 중이라 알리면 포커스를 빼앗지 마세요. 기존 승인 범위에서는 재확인만 반복하지 말고 작업을 진행하세요.

공식4926행은 중복/메타데이터를 포함하므로 실제 고유2243명령과 구분하세요. 지원7행·부분106행·미지원1301행·미확인3512행은 이전 분류이며 새 실행 근거로 갱신하세요. 이전 실패·미실행 이력은 삭제하지 마세요. 새 버전에는 모든 원래 작업을 남기고 각 회차1~5개에 집중하세요. 절차/기대값/의존성 변경은 revision과 scopeChange에 기록하고 영향 QA를 다시 하세요.

게임 데이터·Enum·로컬라이징·Summary와 일반 Excel을 함께 회귀 검사하고, 미저장 닫기/취소/저장 실패/복구·대용량 ArcadeText 입력/스크롤 성능도 검사하세요. UI 변경 후9개 언어 문서의 관련 이미지를 실제로 다시 촬영하고 소스 해시를 맞추세요. 다른 작업의 변경과 현재 배포본을 보존하고 승인 없이 버전/브랜치/배포 범위를 바꾸지 마세요.

중간 보고서 게시를 전체 작업 종료로 삼지 마세요. 실제로 남은 항목은 명확히 남기고 계속 진행하세요. 모든 작업의 현재 revision QA와 전체 final QA가 통과한 뒤에만 전체 완료로 등록하세요. 최종 결과는 실제 실행 이미지가 포함된 로컬/공개 HTML 보고서, 케이스별 원본/현재 대조, 전체 단축키 매칭표, 남은 항목0의 검증 근거로 제출하세요. 소요 시간과 XERJ 사용/실패를 사실대로 기록하세요.
