## 작업 결과

설정 경로를 Assets/TurnRoom/DesignDataTable/Resources로 수정했습니다. 새 프로젝트의 실제 패키지 설치에서 기존 초기화 오류는 재발하지 않았습니다.

## 변경 내용

### 재현 조건

Unity 6000.0.83f1 · 새 Windows 프로젝트 · 네 제품 패키지 순차 설치

### 재현 순서

기존 TurnRoom 에셋이 없는 새 프로젝트에 실제 .unitypackage를 가져옵니다.

### 기대 동작

기존 패키지 설정 파일을 보존하며 현재 제품 폴더에서 초기화해야 합니다.

### 실제 동작

최초 검사에서 Assets/DesignDataTable/Resources/TableManagement.asset 생성 실패가 기록됐습니다.

### 원인

TableManagement의 이전 고정 경로와, 패키지 설정 에셋이 아직 import되지 않은 동안 즉시 CreateAsset을 호출하던 흐름을 소스와 오류 로그로 확인했습니다.

### 적용 내용

현재 경로를 사용하고 import 중에는 임시 인스턴스를 사용합니다. 기존 파일을 덮어쓰지 않으며, import 후 실제 에셋을 읽을 수 있으면 이를 다시 채택합니다.

## 검증

별도의 새 프로젝트 ReleaseVerifiedImport20261102에서 네 제품 설치12개·샘플 제거 본체8개 검사 통과. 설치 오류0건, 이전 경로 설정 파일 생성 없음. 실제 설치 파일3,646개를 대조했고, 다른346개 C# 파일은 독립된 주석 언어 설정에 따른 XML 주석 차이뿐임을 Roslyn 실행 토큰 비교로 확인했습니다. Data Table 기능20개도 통과했습니다. 코드/초기화 변경이므로 전후 화면을 억지로 만들지 않았으며 실제 로그·코드·설치 결과를 근거로 사용했습니다.

## 남은 사항

이 오류와 별개로, 재생성 중인 패키지를 읽어 발생한 QA 도구 경합도 보존했습니다. 파일·해시를 고정한 후 재실행했습니다.

## 작업 시간

- 제안 시간: 4개 제품 전체 작업 예산 최대10시간에 포함.
- 실제로 완료된 시간: 수정·재검증은 전체10시간 작업 예산에 포함됩니다. 새 프로젝트 설치 완료: 2026-11-02 08:36:48 KST. 최초 수정 착수 시각은 별도로 기록되지 않아 해당 오류만의 정확한 소요 시간은 미확인입니다.
- XERJ: 사용 — XERJ TableManagement 검색 후보를 현재 소스에서 확인했습니다. Runtime 소스는 인덱스 범위 밖이므로 rg로 경로·CreateAsset 호출을 대조했습니다.
