## 변경 내용

### 적용 내용

게임 코드나 설정은 수정하지 않았습니다. 최초 명세와 현재 소스·README·DB 스키마·직전 실행 검증 JSON을 대조했습니다. 과거 구현 완료 보고의 범위를 전체 기획 완료로 확대하지 않았습니다.

## 검증

server/src/game.ts에서 실제 생존 감소, 고정 수색 테이블, NPC 거래 분기, 스폰 후보, 월드 구분을 확인했습니다. server/src/server.ts에서 JSON 저장과 127.0.0.1 바인딩을 확인했고 PostgreSQL 호출은 없습니다. database/001_initial.sql은 목표 스키마이며 실행된 DB 연결의 증거가 아닙니다. 현재 maxPlayers=100은 월드별 동시 접속 부하 검증 결과가 아니라 캐릭터 생성 제한 및 서버 전체 접속 상한에도 사용되는 설정이므로 월드마다 100명 지원이 완성되었다고 판단하지 않았습니다. Assets/Scripts/GameClient.cs와 README에서 OSM 보조 지도와 Windows 전용 상태를 확인했습니다. docs/character-runtime/verification.json은 직전 게임 실행에서 4개 캐릭터 모션을 확인한 기록이며 이번 검토에서 새로 게임을 실행한 결과로 보고하지 않습니다. 이번은 문서·소스 대조 검토여서 새 실행 화면을 만들지 않았고 기존 캐릭터 보고서의 실제 게임 화면과 이번 검토 결과를 구분합니다.

## 남은 사항

권장 개발 순서는 다음과 같습니다. 이는 후속 작업 제안이며 이번 검토에서 해당 기능을 구현한 것은 아닙니다.

1. 실제 수원 중 작은 구역을 정해 도로·건물 배치와 수색 장소를 연결하고, 탐색 → 수색 → 소비/회복 → 캠프 복귀의 플레이 흐름을 완성합니다.
2. 활력 소모·휴식·허기/갈증 고갈 효과, 비접속 규칙, 물자 재생성/공유 규칙을 확정하거나 설정으로 분리해 구현합니다.
3. PostgreSQL/PostGIS 저장소를 연결하고 월드별 가변 상태·아이템 지급/거래 트랜잭션·재접속/재시작 복원을 검증합니다.
4. NPC 대화·상점·치료 UI와 다자 플레이를 정리하고, 월드별 동시 접속 상한과 관심 영역 전송을 구현해 100명 부하를 검증합니다.
5. 최초 브라우저 목표를 유지한다면 Unity Web 빌드 지원과 브라우저 WebSocket 계층을 연결해 별도 검증합니다.

전투·세력·차량 등을 초기 프로토타입 필수로 임의 추가하지 않습니다. 미정 생존 규칙도 이번 검토에서 확정하지 않았습니다.
