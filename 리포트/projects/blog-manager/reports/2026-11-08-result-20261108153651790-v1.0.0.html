게시물 하단 관리 UI 정리·중복 편집기 버튼 제거 0.10.4

검증 대기

요청한 게시물 하단만 예약 정보·시각 입력·관리 동작으로 정리하고 네이버 편집기로 버튼을 제거했습니다. 설치된 확장 파일까지 반영했으며 실제 크롬 시각 검증은 남았습니다.

2026년 11월 9일 오전 12:36 KSTv1.0.0수정사항

작업 결과

하단 예약 상태·날짜/남은시간, 시각 입력과 시간변경, 원고수정/내려받기/예약취소를 구분했습니다. 이미 등록한 예약글에서는 중복 제출이 되는 즉시발행을 숨기고 원고수정을 주 버튼으로 표시합니다. 태그·본문의 원래 틀은 유지합니다.

변경 내용

적용 내용

  • 모든 버튼을 같은 줄에 나열하던 구조를 예약 요약·시각 입력·관리 동작의 세 구역으로 재배치했습니다.
  • 네이버 편집기로 버튼과 해당 하단 클릭 핸들러를 제거했습니다. 예약 원고 수정은 기존 원본 수정 경로를 유지합니다.
  • 입력/버튼 높이38px·간격8px·얇은구분선·단일녹색주동작으로 통일했습니다. 취소는 우측의 텍스트형 동작, 주제 제외는 접힌 추가 설정으로 분리했습니다.
  • 원고 파일 ZIP은 원고 내려받기로 바꿨고 빈 상태 메시지는 표시하지 않습니다. 좁은 화면에서 줄바꿈하도록 CSS를 추가했습니다.
  • 로컬 편집 중에는 예약 설정·예약 취소를 숨기며 저장/취소 후 복원합니다.

검증

전체64/64검사 통과·건너뜀0. 새2개격리DOM검사에서 예약글즉시발행숨김·네이버편집기로없음·원고수정경로·기존태그/본문/외부영역보존·로컬편집취소후원본DOM복원을 확인했습니다. 실제공개원문HTML에 코드재실행해4열·태그·편집저장/취소·확인취소/중복클릭회귀검증통과. 이 검사는 브라우저 실화면 또는 실제발행검증을 대신하지 않습니다. 설치확장0.10.4의 변경2파일해시일치·원고파일SHA불변. 실행서버는기존0.10.3을유지하며 재시작하지 않았습니다. 전체설치본0.10.4는159841311바이트,SHA256 F417B9CA0D26593C11604C44F7423358C096391A1AA35470A4B0C055E394FBE2입니다.

남은 사항

크롬확장재로딩·기존블로그페이지새로고침후 실제시각검증미완료. 사용자화면비조작조건으로 OS컴퓨터유즈·직접크롬조작·스크린샷촬영은 수행하지 않았습니다. 기존 미완료 항목·QA이력은 보존합니다.

대화 요약(개별발언시각미기록): 사용자 첨부화면의 하단영역만 다시디자인하고 “네이버 편집기로 버튼 없애고 깔끔하게” 요청 → AI 5~10분 예상,본문/태그 유지·화면비조작 제시 → 하단그룹/버튼/CSS변경 → 격리DOM·전체64검사 → 설치확장2파일적용. 이전 사용자의 “컴퓨터 유즈 쓰지마셈” 지시를 유지했습니다.

첨부된 변경 전 화면에는 미게시 원고 본문이 포함되어 공개 복사하지 않고 대화 첨부로 보존했습니다. 변경 후 실제 화면은 촬영하지 않았으므로 전후 시각 비교 완료로 보고하지 않습니다. UI는HTML/CSS로 구현했으며 이미지자산제작/편집은 하지 않았습니다.

교훈 검토: 하단 관리 구역 분리·중복 편집기 버튼 제거 선호를 기존 프로젝트 UI지침에 통합했습니다. 전역은 기존 범위준수·실제검증구분 원칙과 중복돼 변경하지 않았습니다. 새GUI·탭·임시서버를 만들지 않았고 컴파일 프로세스는 정상 종료했습니다. 사용자 기능을 위한 기존앱은 유지합니다.
