작업 결과

WindowFrame.AddResizeHandles의 가장자리 영역을 8px, 모서리를 14px로 변경했습니다. 각 방향의 커서를 표시하고, 실제 잡은 핸들 영역 안에서만 커서를 등록합니다.

변경 내용

적용 내용

기존 소스에는 5px 영역과 방향 커서 부재가 확인됐습니다. 크기 조절 시작도 CanControl의 네이티브 창 검색 성공 여부에 묶여 있었습니다. 떠 있는 창의 owner.position 변경은 이 별도 제어 가드와 분리하고 도킹·최대화 제한은 유지했습니다. 반복 호출 시 기존 핸들을 제거해 중복을 방지합니다. 커서용 IMGUI 자식은 PickingMode.Ignore라 부모 포인터 캡처를 가로막지 않습니다. 기존 8방향 Resize 계산과 최소 크기 적용은 유지했습니다. Entity Forge 전용 복제가 아닌 공유 템플릿 수정입니다.

검증

비GUI 검사 근거. 8방향 영역의 둘레/중앙 포함 여부와 중복이 없는지 수학 모델로 검사했습니다. 4방향 커서 및 가드/포인터 캡처 코드를 확인하고 공유 Editor를 포함한 7개 어셈블리 컴파일·현재 소스 해시를 대조했습니다. Entity Forge 패키지 400개 에셋 바이트 대조 통과. SHA-256 177500f0dc4dbb8f1e478c90a9b83a1b918393014d4cd3b0d68a2172942078a3. 화면 조작·에디터 명령·실제 빌드는 하지 않았습니다.

남은 사항

사용자 환경에서 실제로 마우스가 잡히지 않은 단일 원인은 미확인입니다. 소스상 확인된 좁은 영역·커서 부재·제어 가드 결합을 보강했습니다. 수학 모델은 네이티브 hit-test 통과가 아닙니다. 실제 8방향 드래그·커서·도킹/최대화 회귀와 제품별 화면 검증은 사용자 화면 조작 금지로 미실행이며 전후 캡처도 확보하지 않았습니다. 교훈 검토: 포인터 대상과 커서 영역을 같은 로컬 경계로 제한하고 창 제어 가드의 역할을 분리했습니다. 이번 상세는 프로젝트 메뉴얼에 기록하며 기존 승인/실제 검증 지침과 중복되는 전역 규칙은 추가하지 않습니다.
