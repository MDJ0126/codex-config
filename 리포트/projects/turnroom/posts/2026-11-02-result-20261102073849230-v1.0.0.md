## 작업 결과

사용자가 지적한 순서 변경을 첨부 화면과 현재·이전 소스 대조로 확인했습니다. 이번 검토에서는 배치 코드를 변경하지 않았습니다.

## 변경 내용

### 적용 내용

8810bebc에서 UnityEditor.AppStatusBar 내부 트리 확장 방식이 별도 WorkbookShelfWindow 방식으로 바뀌었습니다. 현재 WorkbookMinimizedShelf.cs:997은 main.yMax-48 위치에 높이28의 창을 놓으므로 하단20px가 리스트 아래에 남습니다. 이전 코드는 WorkbookStatusBarLayout.Reserve로 높이를28px 늘리고 상태줄 트리 끝에 리스트를 추가했습니다.

## 검증

현재 소스의 좌표 계산, WorkbookStatusBarLayout.cs의 높이28, git show 8810bebc^의 이전 tree.Add 및 Reserve 호출을 직접 대조했습니다. 첨부 화면은 사용자가 제공한 실제 Unity6000.0.83f1 화면입니다. 화면 조작 중지 상태를 유지해 신규 실행·캡처는 하지 않았습니다. 현재 및 이전 소스 확인만으로 네이티브 재배치 검증이 끝났다고 판단하지 않았습니다.

## 남은 사항

아래 공간을 확보하면서 콘솔줄과 리스트 순서를 보존하는 구현·실제 Unity 배치 검증이 남았습니다. 좌표만28px 내리는 변경은 콘솔줄을 덮으므로 적용하지 않았습니다. 기존 내부 Unity API를 복원할 경우 판매 패키지 정책과 호환성 검토가 필요합니다. 교훈 검토: 기존 실제 화면 검증·미검증 표시 규칙에 포함되어 전역 지침 변경 없음.
