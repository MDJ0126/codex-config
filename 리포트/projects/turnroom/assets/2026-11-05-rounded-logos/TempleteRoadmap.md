# 공통 템플릿 제품 개발 체크리스트

작성일: 2026-11-01 (Asia/Seoul)

제품을 계속 추가할 때 재사용할 공통 템플릿의 작업 목록입니다. 새 제품을 시작하거나 공통 UI를 변경하기 전에 이 목록과 [기존 템플릿 가이드](TempleteGallery.md)를 확인합니다.

이 문서는 요구사항과 검토 후보를 기록합니다. 체크되지 않은 항목은 구현 부재를 뜻하지 않으며, 현재 구현·검증 상태는 별도 확인이 필요합니다. 이번 기록 요청은 아래 기능 전체의 구현 지시가 아닙니다.

## 사용자 지정 필수 항목

- [ ] **로고 배경의 둥근 외곽**: DDT와 템플릿 기반 제품 및 Pixora 하위 제품(Image Maker·Pixel Camera·Pixel Foliage)의 로고 배경은 Entity Forge처럼 둥근 모서리로 제작합니다. Pixora Studio 제품군 대표 로고만 예외로 기존 외곽 형태를 유지합니다. 실제 Affinity 편집 원본에 모서리를 반영하고, 출력 이미지의 바깥 모서리는 투명하게 보존합니다. UI 클리핑만으로 대체하지 않고 작은 아이콘·원본 크기에서 윤곽과 투명도를 확인합니다. 템플릿 전용 예제 로고는 `Assets/TurnRoom/Templete/Development/Art/ExampleLogo/`에서 관리하며 제품 고유 로고 대신 배포하지 않습니다.

- [ ] **판매 미디어 품질**: [제품 출시 체크리스트](ProductReleaseChecklist.md)를 적용합니다. DDT 스타일의 실제 기능 갤러리, 편집 가능한 Affinity 원본, 들리는 영상 오디오·권리·청취 검증, 포털 저장 후 재확인을 완료 조건으로 둡니다. 무음 영상과 반복 이미지로 통과 처리하지 않습니다.

- [ ] **9개 언어의 제품 UI**: 영어 기본과 한국어·일본어·중국어 간체/번체·스페인어·프랑스어·독일어·브라질 포르투갈어를 창·Inspector·선택 항목·툴팁·상태/오류에 적용합니다. `TemplateLanguage` 전역 설정을 공유하고 이미 열린 UI도 갱신합니다. 문서 번역이나 이벤트 연결만으로 완료 처리하지 않습니다. 번역 누락·치환 인자·실제 전환·긴 문구 배치를 검증합니다.
- [ ] **어셈블리와 샘플 격리**: Runtime·Editor·선택 통합·샘플 Runtime/Editor·개발/QA를 명시적 `.asmdef`로 분리합니다. 에디터 언어 자원은 Editor 안에 둡니다. 샘플은 본체를 참조하고 본체는 샘플을 참조하지 않습니다. 샘플·개발 폴더 제거 후 본체 컴파일, 가져오기 전후 기존 씬·빌드 프로필·프로젝트 설정 보존을 검증합니다. 예제를 자동 실행하거나 선택 패키지 설치·빌드 변환을 자동 활성화하지 않습니다.
- [ ] **간결한 판매 페이지**: 목적·핵심 기능·검증된 호환 버전·필수 의존성·중요 제한만 간결하게 작성합니다. 제품 UI 번역과 별도로 포털이 지원하는 언어별 판매 필드와 해당 AI 고지를 작성하고, 전체 새로고침 후 저장값을 대조합니다. 셀러 초안의 저장·재열기를 확인하고 최종 제출은 별도 사용자 지시가 있을 때만 합니다.

- [ ] **새 제품별 고유 기본 테마 색상**: 새 제품을 만들 때 기존 제품에서 사용하지 않는 새로운 기본 테마 색상으로 시작합니다. 생성 전에 기존 제품의 테마 설정과 색상값을 대조하고 선택한 색상값을 제품 문서에 기록합니다. 제품 테마 설정에서 관리하고 하위 창·Inspector·팝업은 해당 제품의 테마를 상속합니다. 공통 템플릿의 기본색을 그대로 새 제품의 기본색으로 사용하거나 다른 제품의 기본 테마 색상을 재사용하지 않습니다.

- [ ] **헬프박스 공통화·모든 제품 적용**: UI Toolkit은 `TemplateHelpBox`, Inspector·IMGUI는 `TemplateHelpBox.Draw`를 사용합니다. 정보·경고·오류의 의미와 번역을 보존하고, 모체의 글꼴·여백·테마를 공유합니다. 신규 제품도 독자적인 기본 HelpBox를 추가하지 않습니다. 구현과 컴파일 완료 여부 및 실제 화면·문서 검증 상태는 개별 QA 기록으로 구분합니다.
- [ ] **새 제품군·제품별 고유 로고 제작·동일 파비콘 적용**: 새 제품군이나 제품을 만들 때마다 기존 제품과 구별되는 고유 로고를 새로 제작합니다. 실제 Affinity에서 편집 가능한 원본과 출력물을 해당 제품 폴더에 보관하고, 확정한 동일 로고를 제품 UI·모든 지원 언어의 다큐먼트 파비콘·필요한 배포물에 적용합니다. 파비콘의 아이콘 링크·배포 자산·실제 브라우저 탭 표시를 확인하고 작은 크기 및 라이트/다크 배경의 가독성을 검증합니다. 기존 템플릿·다른 제품의 로고가 남거나 로고 제작·적용·파비콘 검증이 빠진 상태로 새 제품 작업을 완료 처리하지 않습니다.
- [ ] **에셋 Inspector 상속·공통 디자인**: 생성되는 프리셋·프로필·팔레트·작업 파일·테이블 에셋의 Inspector는 `TemplateAssetInspector`를 상속합니다. 임포터는 `TemplateImporterInspector`로 Apply/Revert를 보존합니다. 제목·설명·속성 카드·작업 버튼·헬프박스는 모체에서 공유하고 실제 편집·Undo·저장·재열기를 검증합니다.
- [ ] **다큐먼트**: 설치, 시작하기, 기능별 사용법, 확장 방법, 문제 해결을 정리합니다. 실제 UI와 안내를 대조하고, 지원하는 9개 언어의 설명·스크린샷 갱신 규칙을 따릅니다.
- [ ] **샘플 씬 10개**: 기능별 예제와 조합 예제를 구성합니다. 각 씬의 목적, 실행 절차, 기대 결과를 기록합니다. 구체적인 10개 주제는 추후 확정합니다.
- [ ] **디자인 팝업 상속·공통 사용**: 공통 부모, 호출 API, 입력·결과·취소 계약과 제품별 확장 방법을 정리하고 실제 제품 적용을 검증합니다. 모든 제품 창에서 필드 생성 후 `UITemplate.Apply`를 호출해 ObjectField·ColorField·DropdownField·EnumField의 공통 선택 패널을 자동 연결합니다. 명령·오류 패널은 `TemplateInspectorPopover.Show`를 사용하고 새 제품에서 Unity 기본 메뉴·오브젝트 선택창·알림창을 직접 호출하지 않습니다. 생성·패키징 전 정책 검사와 실제 선택값·취소·소유 테마 상속 QA를 수행합니다. 운영체제 파일 선택창은 구분합니다. “템플릿을 이용해 새 제품을 만든다”는 요청 자체에 공통 커스텀 팝업 적용을 포함합니다. 최초 구현부터 제품 창·하위 창·에셋/컴포넌트/임포터 Inspector·동적 생성 필드·빈 상태·오류 상태에서 Unity 기본 팝업 디자인을 노출하지 않습니다. 지원하지 않는 선택 UI가 있으면 공통 템플릿을 먼저 확장하며 기본 Unity 팝업으로 자동 대체하지 않습니다. 라이트/다크에서 실제 마우스·키보드 선택과 바인딩 값 반영·취소·제품 테마 상속을 확인해야 완료이며, 정책 검사나 팝업 열기만으로 통과 처리하지 않습니다. 화면 제어가 중단된 경우 미실행 QA를 보류로 남깁니다.

## 추가 검토 후보

아래 항목은 대화에서 제안한 후보이며 개별 채택·우선순위는 미확정입니다.

- [ ] **공통 윈도우 구조**: 타이틀바, 툴바, 사이드바, 상태바, 창 수명 관리
- [ ] **공통 UI 컨트롤**: 입력창, 드롭다운, 슬라이더, 벡터, 색상·에셋 선택기
- [ ] **디자인 시스템**: 여백, 높이, 글꼴, 아이콘, 강조색, 라이트·다크 모드
- [ ] **공통 상호작용**: 마우스·키보드 선택, 포커스, 단축키, 드래그 앤 드롭
- [ ] **설정·상태 저장과 복구**: 사용자 설정, 창 상태, 미저장 변경 안내, 복구 흐름
- [ ] **안내·오류 처리**: 툴팁, 빈 화면, 로딩, 진행률, 오류·확인 메시지
- [ ] **확장용 기본 골격**: 새 창·팝업·컨트롤을 추가하는 최소 코드와 예제
- [ ] **패키지·배포 구성**: 의존성, 지원 Unity 버전, 개발 도구 제외, 설치·업데이트 검증
- [ ] **공통 회귀 QA**: 실제 Unity에서 테마, 배율, 다중 창, 재시작, 입력값 반영 검증

## 제품 추가 시 사용 방법

- Inspector 속성은 `TemplateInspectorUI.SerializedField`로 생성합니다. Templete 1.5.0의 공통 배열·중첩 카드와 색상·Enum·에셋·레이어 선택 패널을 사용합니다. Pixora 컬러 목록의 실제 추가·삭제·이동·RGBA·Undo와 저장 재열기는 검증했습니다. 전체 공통 QA 완료와는 구분하며 유틸리티 Inspector의 Escape 동시 닫힘은 남아 있습니다. 근거: `Docs/Testing/2026-11-01/shared-property-lists/`.

1. 필수 항목과 채택한 후보의 기존 구현·문서·실행 결과를 확인합니다.
2. 제품 고유 기능과 공통 템플릿의 책임을 정하고 중복 구현을 피합니다.
3. 실행 메뉴얼에 구현·제품 적용·문서 갱신·QA를 구분해 등록합니다.
4. 실제 실행과 회귀 QA 근거가 확보된 범위만 완료 표시하고 관련 보고서를 연결합니다.

## 기록 검증

- 원래 목록의 필수 3개와 추가 후보 10개를 보존하고, 사용자 요청으로 새 제품별 로고 제작·적용과 헬프박스 공통화를 필수 항목에 추가했습니다.
- 기능 구현 여부와 샘플 씬의 세부 주제는 이번 문서 기록 작업에서 검증하지 않았습니다.
- 문서만 추가하므로 프로그램 실행 화면 캡처 대상은 없습니다.
- XERJ: 미사용 — 코드 검색 불필요
- 교훈 검토: 전역 지침 변경 없음. 지속 사용할 프로젝트 체크리스트와 참조 경로만 기록합니다.

- [ ] 제품 다큐먼트는 DDT 기준과 ProductDocumentation.md의 공통 생성기·9언어 예제를 재사용한다. 개요/빠른 시작·실제 예제1장·고유 헤더/카테고리 로고·파비콘·배포 자산 검사와 실제 브라우저 QA를 완료 기준으로 둔다. 공통 생성기·27개 언어판 생성 및 경로/동작 검사는 구현·실행했고 native 시각 QA는 미실행으로 남긴다.
