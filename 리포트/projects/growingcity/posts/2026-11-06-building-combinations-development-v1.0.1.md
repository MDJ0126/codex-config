## 작업 결과

자동 성장을 단순 건물 추가에서 인접 조합에 따른 진화와 단지 형성으로 확장했습니다. 주택A+B는 두 구역을 쓰는 아파트, 아파트 두 동은 네 구역의 상위 건물로 바뀝니다. 상점+오피스는 건물을 유지한 상업 단지가 됩니다. 왼쪽 위 도시 발전도는 생성·진화 시 오르고 파괴 시 내려갑니다.

## 변경 내용

### 적용 내용

- 주택A(10)+주택B(12) → 아파트40: 기존 두 건물을 제거하고 두 칸의 점유를 하나의 건물로 관리합니다.\n- 아파트40+아파트40 → 상위 건물100:2×2 네 칸을 함께 점유합니다. 등록되지 않은 조합과 대각선 배치는 진화하지 않습니다.\n- 상점14+오피스18 → 연결 단지: 두 건물을 유지하며 연결당12의 발전도 보너스와 공동 보행 공간을 갖습니다. 연결이 블록 경계를 가로지르면 내부 도로를 제거하고 주변 도로 방향도 다시 계산합니다.\n- 발전도는 현재 생존 건물 가치+현재 연결 보너스의 합입니다. 누적 파괴 점수와 별도입니다. 진화 건물의 어느 점유 칸이 맞아도 한 건물로 한 번만 파괴되며 전체 점유 칸을 비웁니다. 재건은 빈 칸을 순차 회복하고 조합을 다시 평가합니다.\n- 규칙 에셋 Assets/Settings/City Combination Rules.asset에서 입력 종류·결과·단계·발전도·최대 점유 크기와 단지 종류·보너스를 편집할 수 있습니다. 현재 시제품의 진화 모양은 직사각형이며 최대2×2입니다.\n- 여러 칸 건물은 원본 에셋의 인스턴스를 전체 점유 폭에 맞추고 하나의 충돌체로 관리합니다.\n- 왼쪽 위 기존 Title·Tagline Text를 도시 발전도 라벨과 값으로 직접 편집했습니다. 정적 라벨은 한글 글리프가 있는 Noto CJK 폰트에 씬에서 연결했고 런타임 UI 생성·폰트 대입은 추가하지 않았습니다. 폰트 원본과 OFL 라이선스를 보관했습니다.

## 검증

실행한 검사47개 통과: 기존24개 성장·파괴·재건·도로 회귀와 신규23개 조합·다중 구역 소유권·대각선/미등록 거부·전멸·단지 연결·중간 구성원 파괴·발전도 감소·중복 점수 방지·100회 성장의 단조 증가와 반복 파괴 후 비음수 발전도 검사입니다.\n\nRuntime·Editor C#을 설치된 Unity6000.0.83f1 참조 라이브러리 대상으로 컴파일 통과했습니다. 씬 정적 검사는121개 오브젝트·244개 로컬 참조·74개 외부 참조·5개 버튼 이벤트를 확인했습니다. 규칙 에셋 두 개 진화식과 보너스, 발전도 Text 참조, 한글 라벨 실제 cmap 글리프와 기존12개 영문 Text의54종 문자 누락0을 확인했습니다. 원본 Low Poly Epic City5,840개 파일 해시 변경0건입니다.\n\n다중 구역 건물은 축을 맞춰 크기 정규화 후 회전하며, 직사각형 두 칸 건물은0/180도만 허용해 크기 축이 바뀌지 않도록 했습니다.\n\n컴퓨터 유즈·Unity 신규 실행·재시작·Play·스크린샷은 사용자의 화면 사용 조건으로 미실행입니다. 정적 참조와 독립 실행 검사를 실제 Unity 표시·조작 검증으로 보고하지 않습니다. 가짜 화면을 만들지 않았습니다. 교훈 검토: 기존의 원본 보존·UI 직접 저장·검증 범위 구분 규칙으로 충분하여 전역 지침 변경 없음.
