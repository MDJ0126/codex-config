작업 결과

건물 하나로 시작해 인접 구역으로 자동 성장하고, 클릭한 곳을 폭파해 점수를 얻으며 빈자리를 자동 재건하는 첫 시제품 코드를 작성했습니다. 전용 씬은 Assets/Scenes/City Prototype.unity입니다. 실제 게임 화면·브라우저 동작은 아직 검증하지 않았습니다.

변경 내용

적용 내용

  • 자동 성장: 약 1.15초 간격, 주택에서 중층·고층 에셋까지 단계적으로 등장. 구역 테두리의 도로를 공유합니다.\n- 등장 효과: 약 0.65초의 커졌다가 안착하는 애니메이션.\n- 카메라: 살아 있는 건물·외곽을 투영해 부드럽게 확대·축소. 가운데만 비고 외곽이 남으면 전체 시야는 유지합니다.\n- 파괴: 일반 폭탄과 핵폭탄, 건물 단위 붕괴, 상한이 있는 물리 잔해·충격파·버섯구름 연출·합성 타격음. 실제 구조 파괴 물리와는 구분합니다.\n- 점수: 건물 등급과 동시 파괴 수로 계산하며 같은 폐허에는 중복 지급하지 않습니다.\n- 재건: 약 4.5초 뒤부터 빈자리를 우선 복구. 전멸해도 복구하며 점수는 유지합니다.\n- UI: 씬에 편집 가능한 Canvas·Text·Button 25개 GameObject와 5개 Inspector 이벤트. 1/2 무기 선택, Space 일시정지, 1배/3배, 초기화. UI 런타임 생성 코드 없음.\n- Core·Runtime·Editor 어셈블리 분리. 웹 빌드 메뉴를 추가했으며 기존 Build Settings 씬 목록은 보존합니다.\n- 외부 에셋 원본을 수정하지 않고 생성된 인스턴스에만 필요한 머테리얼 대체를 적용합니다.

검증

실행한 검사:\n1. .NET 핵심 시나리오 16개 통과: 단일 시작·인접 성장·지연·범위 폭파·점수·중복 방지·빈자리 우선 재건·전멸·반복 복구·선택적 제한·시드 재현·잘못된 입력 거부. 첫 검사에서 기존 폐허의 복구 시각과 전멸 시각을 혼합한 기대값이 실패하여 격리된 전멸 시나리오로 검사 조건을 바로잡았으며, 최초 결과도 로컬에 보존했습니다.\n2. 설치된 Unity 6000.0.83f1 라이브러리를 대상으로 Runtime·Editor C# 컴파일 통과. 이는 Unity 내부 Play 검증을 뜻하지 않습니다.\n3. 씬 정적 참조 검사: 직렬화 오브젝트 121개, 로컬 참조 242개, 외부 참조 54개, 버튼 5개 연결 확인. Unity 씬 로딩·실제 UI 배치·셰이더 렌더 결과를 검증한 것은 아닙니다.\n4. 에셋 원본 5,840개 파일 SHA-256 변경 0건.\n\n사용자의 컴퓨터 사용을 보존하기 위해 컴퓨터 유즈·스크린샷·GUI 신규 실행·재시작·Play·웹 빌드는 수행하지 않았습니다. 실제 화면을 촬영하지 않았으며 가짜 화면으로 대체하지 않았습니다.\n\n근거는 프로젝트 QA/Prototype의 logic-results-v2.txt, unity-compile.txt, editor-compile.txt, scene-verification.json에 보존합니다. 교훈 검토: 기존 원본 보존·검증 범위 구분·포커스 비간섭 규칙으로 충분하여 전역 지침 변경 없음.

남은 사항

실제 Unity 씬 로딩과 Play 조작, 시각적 연결·줌 전환·타격감·음량, 웹 빌드·브라우저 실행·성능은 미검증입니다. 사용자 화면 사용 금지 조건 아래 이 항목을 통과로 표시하지 않습니다.\n\n사용자가 실행할 때 Unity에서 Assets/Scenes/City Prototype.unity를 열고 Play를 누르십시오. 웹 빌드는 Tools > Growing City > Build Web Prototype이며 생성 위치는 Builds/Web입니다. 사람·차량·다양한 재해는 후속 범위입니다. 성장 한계는 기본 무제한(Inspector Max Buildings=0)이며, 실제 웹 프로파일링 후 결정해야 합니다. 잔해는 기본100개, 동시 효과12개로 제한했습니다.\n\n신규 게임 로고·브랜딩 확정은 하지 않았으며 임의 로고를 공식 자산으로 등록하지 않았습니다.
