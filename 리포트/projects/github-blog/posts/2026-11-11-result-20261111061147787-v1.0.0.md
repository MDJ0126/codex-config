## 변경 내용

### 적용 내용

사용자는 합계가 있지만 시간대·기기·페이지 표가 빈 이유를 확인해 달라고 요청했고, 이어 포트폴리오의 본인 방문 제외와 무시 규칙 3개를 가져오라고 요청했습니다. GA 서비스 계정 설정이 없을 때 사용하는 응답이 상세 항목을 빈 배열로 반환하고 있었습니다. 기존 방문 기록 저장소를 집계에 연결하고 현재 블로그 주소를 허용했습니다. 서버는 무시 규칙을 조회한 뒤 기록하며 클라이언트도 GA 실행 전에 제외 여부를 확인합니다.

```js
export async function visitDetails(env, start, end) {
  const store = env.CRAWLER_REPORTS.get(env.CRAWLER_REPORTS.idFromName('crawler-reports'));
  const url = new URL('https://internal/visitors');
  url.searchParams.set('start', start);
  url.searchParams.set('end', end);
  url.searchParams.set('all', '1');
  const response = await store.fetch(url);
  if (!response.ok) throw new Error('Visit details are unavailable');
  const { records, summary } = await response.json();
  const devices = new Map();
  const landings = new Map();
  const recent = new Map();
  const clock = new Intl.DateTimeFormat('sv-SE', { timeZone:'Asia/Seoul', year:'numeric', month:'2-digit', day:'2-digit', hour:'2-digit', hourCycle:'h23' });
  for (const row of records) {
    const device = /ipad|tablet/i.test(row.userAgent || '') ? 'tablet' : /mobile|android|iphone/i.test(row.userAgent || '') ? 'mobile' : 'desktop';
    devices.set(device, (devices.get(device) || 0) + 1);
    const page = new URL(row.pageUrl);
    if (!row.referer || !row.referer.startsWith(page.origin + '/')) landings.set(page.pathname, (landings.get(page.pathname) || 0) + 1);
    const hour = clock.format(new Date(row.submittedAt)).replace(/[- :]/g, '').slice(0, 10);
    const key = JSON.stringify([hour, row.city || row.country || '알 수 없음', device]);
    recent.set(key, (recent.get(key) || 0) + 1);
  }
  return {
    hours: summary.hours,
    devices: [...devices],
    cities: summary.cities,
    pages: summary.pages,
    sources: summary.sources.map(([name, count]) => [name, 'referral', count]),
    landings: [...landings].sort((a,b) => b[1]-a[1]).slice(0, 10),
    recent: [...recent].sort((a,b) => b[0].localeCompare(a[0])).slice(0, 10).map(([key,count]) => [...JSON.parse(key), count]),
  };
}
```

## 검증

- 포트폴리오 원본 무시 규칙 3개, 복사된 블로그 규칙 3개, 조건 일치 3개를 확인했습니다. IP와 기기 ID 원문은 보고서에 포함하지 않았습니다.
- 각 규칙을 조회했을 때 모두 ignored=true가 반환됐습니다.
- 현재 접속을 블로그에서 조회했을 때 제외 대상으로 판정됐습니다.
- 운영 브라우저에서 제외 플래그와 GA 비활성화를 확인했고 방문 저장 요청과 Google 태그 요청이 발생하지 않았습니다.
- 운영 집계에 영향을 주지 않는 별도 저장소에서 상세 레코드를 생성하고 시간대·기기·도시·페이지·유입·첫 진입·최근 방문 배열이 채워지는 것을 확인한 후 레코드를 삭제했습니다.
- 원래 운영 상세 기록 수는 0개였습니다. 이전 합계에 해당하는 상세 기록은 복원할 자료가 없습니다.
- 수정 대상은 데이터 수집과 API입니다. 관리자 로그인 세션에는 접근하지 못했으므로 로그인된 관리자 화면의 변경 후 캡처와 실제 표시는 미확인입니다.
